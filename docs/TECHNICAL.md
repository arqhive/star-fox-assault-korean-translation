# 기술 메모

일본판 `Star Fox: Assault` (GF7J01, GameCube) 의 파일 구조와 한글화 방식 정리.

## 파일 시스템

- 표준 GC 이미지. 헤더 `0x420` = DOL 오프셋, `0x424` = FST 오프셋/크기.
- 디스크 파일 1090개. FST 뒤 `0x2C8000` ~ 데이터 시작 사이에 참조되지 않는 패딩이 약 96MB 있다.
- 빌드는 원래 파일 순서를 유지한 채 4바이트 정렬로 다시 채우고(`kolib.rebuild_iso`),
  늘어난 만큼 데이터 시작 위치를 앞으로 당겨 디스크 크기(1,459,978,240 바이트)를 그대로 둔다.
- 새 DOL은 패딩 영역 `0x2C8000` 에 두고 헤더 `0x420` 을 고친다.

## 컨테이너 (.fpc / .pac)

```
컨테이너: [항목 수][오프셋 …][끝 오프셋]      ← 재귀 구조
NPAC:     'NPAC', 전체 크기(0x20 헤더 포함), 데이터 크기, 인덱스
```

- 빈 NPAC 은 전체 크기 0, `0xFFFFFFFF` 는 앞 블록의 텍스처를 공유한다는 자리표시자.
- `tools/fpctree.py` 가 이 구조를 트리로 읽고 바이트 단위로 되돌린다(원본 왕복 일치 확인).

## 텍스트 (SELT)

```
'SELT', 항목 수, 언어 수(2), 0
항목 0x18바이트 = 이름 16 + 언어별 오프셋 2개   (lang0=일본어, lang1=영어)
문자 코드 32bit: 0=끝, FFFFFFFF=줄바꿈
```

| 코드 | 뜻 |
|---|---|
| `C000xxxx` | SJIS/ASCII 문자 — 본체 ROM 폰트로 그림 (메뉴·결과 화면) |
| `0x20 \| 폭<<16 \| 글리프번호` | 장면별 글리프 아틀라스 참조 (스토리 대사·자막) |
| `A000:n` | 화자 헤더 |
| `40xx–4Fxx:n` | 루비(후리가나) — 한글화하면서 제거 |
| `6018:n` / `6030:n` | 버튼 아이콘 |

스토리 대사는 SELT 바로 앞 NPAC 에 있는 **I4 글리프 아틀라스**(폭 1024, 24×24칸, 한 줄 42칸)를 참조한다.
한글화할 때는 그 장면에서 쓰인 글자만 모아 아틀라스를 새로 그려 넣는다(`kolib.Atlas`).
글자 진행 폭은 한글 22, 공백 8. 무비 자막은 "첫 줄 폭 기준 시작 x + 모든 줄 왼쪽 정렬"이라
빈 글리프로 폭을 채워 가운데 정렬한다.

줄 폭 한계: 무전 408px, 데모 504px. 넘으면 빌드가 멈춘다.

## 메뉴 폰트 (본체 ROM SJIS 폰트 교체)

메뉴·결과·메모리카드 화면은 게임 안에 폰트가 없고 **GameCube 본체 IPL ROM 의 SJIS 폰트**를 쓴다.
(24×24 셀, 8×8 블록 2bpp, 512×512 시트 9장, Yay0 압축 — Dolphin 의 `Sys/GC/font_japanese.bin` 과 같은 형식)

한글화 방식:

1. 한글 음절을 JIS 1수준 한자 칸(`0x889F` ~)에 차례로 배정하고 그 자리에 글리프를 그림
   (인덱스 = `(hi-0x88)*188 + j + 0x2BE`). 세로 위치는 원래 한자와 같은 3~19행.
2. 만들어진 폰트를 Yay0 로 압축해 DOL 새 text 섹션 `0x803A1D00` 에 넣음.
3. `__OSReadROM` 호출(`0x80130088`)을 그 섹션의 복사 스텁으로 바꿔, ROM 대신 우리 폰트를 읽게 함.
4. 힙이 폰트를 덮지 않도록 ArenaLo 상수 2곳(`0x8012BA64`, `0x8012BA9C`)과
   `OSSetArenaLo`(`0x8012D070`) 클램프를 패치.

이름 입력에 쓰는 음절은 코드값이 바뀌면 메모리카드에 저장된 이름이 깨지므로 폰트 배치 맨 앞에 고정한다.

### 이름 입력 글자표

`m2.rel` 의 `0x18040`(히라가나 59칸) / `0x180B8`(가타카나 59칸), 5줄×12칸(마지막 줄 11칸), SJIS 16bit.
이 두 표를 한글 음절표로 바꾼다.

## 텍스처 (NUTC)

| fmt | 형식 | 블록 |
|---|---|---|
| 3 | RGBA8 | 4×4 |
| 4 | CMPR (DXT1) | 8×8 |
| 5 | C4 (팔레트 16색) | 8×8 |
| 6 | C8 (팔레트 256색) | **8×4** — 이 게임 특유. 표준 GX 와 다르니 주의 |

- 헤더 `+0x48` 에 GIDX가 있지만 값이 재사용되므로 **(폭, 높이, 내용 MD5)** 로 텍스처를 식별한다.
  같은 이미지가 여러 GIDX·여러 파일에 복사돼 있어서, 한 곳만 바꾸면 게임에서 일본어가 그대로 남는다.
- 편집은 원본에서 글자 픽셀을 찾아 **같은 줄의 배경색으로 덮고** 한글을 그리는 방식
  (`texedit.retext_auto`). 인페인팅은 얼룩이 남아서 쓰지 않는다.
- 버튼 라벨은 아이콘 오른쪽 끝 + 5px 에서 글자를 시작하고 아이콘 세로 중심에 맞춘다(`icon_label`).
- RGBA8은 4×4 타일마다 AR 32바이트와 GB 32바이트를 나누어 저장한다. 디코딩·인코딩 왕복 시 원본 바이트가 유지되는 것을 확인했다.
- 타이틀은 일본판 텍스처를 직접 편집한다. `build_logo.py`가 하단 일본어 부제를 한글 이미지로 교체하며, 위쪽 영문 로고는 원본 데이터를 유지한다. 북미판 ISO는 빌드에 사용하지 않는다.
- 단색 라벨은 알려진 깨끗한 여백의 색으로 복원한다(`erase`의 `rowcopy`). 값 상자와 테두리는 제거 영역에서 제외하고, CMPR 4×4 압축 블록 경계도 고려한다.

## 화면 배율 주의

게임이 텍스처를 그리는 배율·위치가 화면마다 다르다.
예를 들어 `Ⓐ선택` 과 `START 종료` 는 같은 24px 텍스처지만 화면에서 2px 어긋나게 그려져서,
텍스처 안에서 위치를 보정해야 화면에서 나란히 보인다.
